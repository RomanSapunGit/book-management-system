Guidance for Claude Code working in this repo. Pair with `README.md` (which is the

## Commands

```bash
# Local dev (without Docker)
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload

# Full stack
docker compose up --build       # API at :8000, Postgres at :5432; migrations run on boot

# Tests — easiest path: inside the api container (dev deps + tests are baked in,
# TEST_DATABASE_URL is preset to db:5432/books_test, conftest auto-creates the DB).
docker compose up -d
docker exec api pytest
docker exec api pytest tests/test_auth.py::test_refresh_reuse_revokes_all_sessions

# Or run on the host against the compose Postgres on :5432:
docker compose up -d db
pytest

# Migrations — hand-written only, never autogenerated.
alembic revision -m "describe change"   # then edit migrations/versions/NNNN_*.py by hand
alembic upgrade head
alembic downgrade -1

# Lint
ruff check . && ruff format --check .
```

`pytest` is configured with `asyncio_mode=auto` and session-scoped event loop / fixtures
(`pyproject.toml`). Test isolation is by TRUNCATE between tests, not transaction
rollback — `tests/conftest.py` truncates a fixed list of mutable tables. **If you add a
new mutable table, append it to that list** or tests will leak state.

## Pagination

All list endpoints use `fastapi-pagination` with `LimitOffsetPage[T]`. The shape is
`{items, total, limit, offset}` and the query params are `limit` and `offset`.
`add_pagination(app)` in `app/main.py` wires the resolver — **it must stay after the
`include_router(...)` calls.**

In routes, build an unbounded `Select` and hand it to
`fastapi_pagination.ext.sqlalchemy.apaginate(db, stmt)` — the library applies `limit`,
`offset`, and the count query for you. **Do not** apply `.limit()`/`.offset()` to the
statement yourself; a hand-rolled limit will silently cap the page.

The `(sort_column, id)` tiebreaker in `order_by` is load-bearing for deterministic
pagination — two rows with the same `created_at` can otherwise swap pages between
requests.

## Architectural traps

### Schema lives in `migrations/`, not `models.py`

`app/db/models.py` is the ORM mapping; the **migrations are the source of truth** for
schema (functional indexes, CHECKs, FK behavior, seed genres, `updated_at` triggers).
`tests/conftest.py` builds its schema from `Base.metadata` then **manually re-applies**
the functional indexes and seeds the genre table so tests match production behavior. If
you add a migration-only artifact (a CHECK, a trigger, a functional index), mirror it in
`conftest.py` or tests will pass while production breaks.

### Auth — the `session.commit()` in the reuse-detection path is load-bearing

`app/auth/service.py:refresh_tokens` revokes all sessions when a rotated token is
re-presented, then commits **before** raising 401. Without that explicit commit, the
FastAPI session dependency rolls back the revocation and the attacker keeps access. Don't
"clean it up." Tests `test_refresh_reuse_revokes_all_sessions` and
`test_logout_revokes_only_target` pin both branches.

### Bulk import — `import_sessions` row is written before processing

`app/books/routes.py:import_books` inserts the `ImportSession` row **before** parsing the
body. This is the property that lets a top-level parse failure (400) still record a
queryable session and still count toward the per-hour rate limit. Don't move the insert.

### Size limiting is in middleware, not the handler

`app/middleware.py:MaxBodySizeMiddleware` is pure ASGI: streams `receive()`, aborts with
413 the moment cumulative bytes exceed `settings.bulk_import_max_bytes` (2 MiB). Scoped to
`/books/import` only. The handler does **not** re-check size — the middleware is the
authority. In production, nginx `client_max_body_size` is the primary gate; this is
defense-in-depth.

### Observability — request id is a ContextVar

`app/middleware.py:request_id_var` is set on entry, read by the JSON log formatter, and
included in **every error body** by the exception handlers in `app/exceptions.py`. Any
new exception handler must call the existing `_body()` helper (or equivalent) so the
request id is preserved — that's the property that lets ops correlate a 500 with one log
line.

### Route ordering in `app/books/routes.py`

`/export`, `/import` (POST + GET list), `/{book_id}/similar` are declared **before**
`/{book_id}` catch-alls. FastAPI matches in declaration order — reordering will silently
route `/books/export` to `get_book("export")` and return 404 or 422. When adding a new
non-`{book_id}` route under `/books`, declare it above the catch-all section.

### Authors have no name uniqueness — by design

Migration `0004_drop_authors_name_unique`. Two real people can share a name. Bulk import
therefore *always* creates a new `Author` row per input name — clients dedupe by id.
Don't add the index back, and don't reintroduce a "get-or-create by name" code path in
`app/authors/service.py`.

## Conventions worth knowing

- **Per-domain schemas.** Pydantic schemas live with the domain
  (`app/books/schemas.py`, `app/auth/schemas.py`). There is no central `app/schemas/`
  package.
- **No `_shared.py` / `_helpers.py`.** Inline single-caller utilities. Promote to a
  shared module only after a second caller exists.
- **PATCH uses `extra="forbid"`** and distinguishes unset / null / unknown key (200
  partial / 200 cleared / 422). An empty `author_ids` on PATCH is 409 (books must have
  ≥1 author), not 422 — intentional asymmetry with POST.
- **No silent "future-proofing."** Fields that aren't used today don't get added today.
  Don't pad production code to satisfy an overspecified test — fix the test.

## Anti-patterns to avoid

| Pattern | Use instead |
|---|---|
| `Optional[T]` | `T \| None` |
| `datetime.now()` | `datetime.now(UTC)` |
| Class-based tests | Function-based pytest |

## Keeping this file current

Update CLAUDE.md as part of the same change that invalidates it. A stale CLAUDE.md is
worse than no CLAUDE.md, because future instances trust it.

**Update when your change**:

- Contradicts a claim here (route-ordering rule no longer holds, size cap moved out of
  middleware, refresh-token semantics changed, etc.).
- Introduces a new architectural trap of the same caliber as existing entries — a
  non-obvious invariant, a load-bearing line that looks like boilerplate, a fixture /
  migration coupling that will silently break tests.
- Adds or removes a command someone needs to run the project.

**Do NOT update for**:

- New endpoints, schemas, or service functions that follow existing patterns.
- Refactors that preserve the big picture.
- Bug fixes, dependency bumps, formatting, log-message tweaks.

The bar: would a future instance, starting cold, make the wrong call without this line?
If no, don't add it. When in doubt, leave it out — this file earns its keep by being
short.
