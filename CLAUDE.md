## Commands

```bash
# Local dev (without Docker)
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload

# Full stack
docker compose up --build       # API at :8000, Postgres at :5432; migrations run on boot

# Tests — easiest path: run them inside the api container (dev deps + tests are baked in,
# TEST_DATABASE_URL is preset to db:5432/books_test, conftest auto-creates the DB).
docker compose up -d
docker exec api pytest
docker exec api pytest tests/test_auth.py::test_refresh_reuse_revokes_all_sessions

# Or run on the host against the compose Postgres on :5432:
docker compose up -d db
pytest
# Integration tests skip automatically when Postgres is unreachable; unit tests still run.

# Migrations — hand-written only, never autogenerated
alembic revision -m "describe change"   # then edit migrations/versions/NNNN_*.py by hand
alembic upgrade head
alembic downgrade -1

# Lint
ruff check .
```

`pytest` is configured with `asyncio_mode=auto` and session-scoped event loop / fixtures
(`pyproject.toml`). Test isolation is by TRUNCATE between tests, not transaction rollback —
look at `tests/conftest.py` if a new mutable table is added (it must be added to the TRUNCATE
list, or tests will leak state).

## README divergence (important)

`README.md` describes bulk import as a **CLI seeder** (`python -m app.seed ...`). That has
been replaced. Current reality:

- `POST /books/import` (multipart, CSV/JSON, auth required, rate-limited, 2 MiB cap).
  Takes `author_ids` (UUIDs) and `genre_id` — **not** author/genre names. The old CSV/JSON
  shape from `examples/` (name-based) is no longer accepted; that folder was removed.
  The POST response **is** the full report (`ImportSessionRead`).
- `GET /books/import` — paginated audit list of the caller's own past imports, newest
  first. Strictly scoped to the authenticated user (no per-id detail route; the list item
  carries the full report).
- `GET /books/{id}/similar` for recommendations.
- No `app/seed.py` module exists.
- All list endpoints (`/books`, `/authors`, `/genres`) now use `fastapi-pagination` and
  return `LimitOffsetPage` (`{items, total, limit, offset}`). README still shows the old
  bare-list shapes for `/authors` and `/genres`.
- **Genres are CRUD now**, not a closed predefined set. `POST/PATCH/DELETE /genres` exist
  (auth required). The migration's seed is the initial set of defaults, not a hard ceiling.
  README still describes the "predefined list" property — that property no longer holds.
  Migration `0003_genres_case_insensitive.py` adds `lower(name)` and `lower(slug)` unique
  indexes to mirror authors/users.

If a task asks about the seeder or the `examples/` files, surface this mismatch — don't try
to make the README literally true.

## API client

`insomnia.json` at the project root is an Insomnia v4 export of every endpoint, grouped by
domain (Auth, Books, Authors, Genres, System). Import via Insomnia → Application →
Preferences → Data → Import. Set `base_url`, `access_token`, `refresh_token`, and the
`*_id` env vars in the Base environment after logging in. Keep this file in sync when
adding or changing endpoints — the bar is the same as for CLAUDE.md (update if a future
user would hit a broken request, skip otherwise).

## Pagination

All list endpoints use **`fastapi-pagination`** with `LimitOffsetPage[T]`. The response
shape is `{items, total, limit, offset}` and the query params are `limit` and `offset`
(library defaults). `add_pagination(app)` in `app/main.py` wires the resolver — it must
stay after `include_router(...)` calls.

In routes, build an unbounded `Select` and hand it to
`fastapi_pagination.ext.sqlalchemy.paginate(db, stmt)` — the library applies `limit`,
`offset`, and the count query for you. **Do not** apply `.limit()`/`.offset()` to the
statement yourself; the library will do that, and a hand-rolled limit will silently cap the
page. The `(sort_column, id)` tiebreaker in `order_by` is load-bearing for deterministic
pagination — two rows with the same `created_at` can otherwise swap pages between
requests.

| Endpoint | Pagination |
|---|---|
| `GET /books` | `LimitOffsetPage[BookRead]`. Filters/sort applied before `paginate()`. |
| `GET /authors` | `LimitOffsetPage[AuthorRead]`. `q` substring filter applied before `paginate()`. |
| `GET /genres` | `LimitOffsetPage[GenreRead]`. 15 seeded defaults; appendable via `POST /genres`. |
| `GET /books/{id}/similar` | `LimitOffsetPage[SimilarBookRead]`. A pre-filter restricts the candidate set to books sharing ≥1 signal with the source (author / genre / ±5yr) — the scoring CASE then runs over that bounded set, not the whole table. |

## Architecture

### Invariant placement is deliberate
Per-invariant choices live in the README's "Where invariants live" table. The principle:
**Pydantic for shape and quick rejection, DB for invariants that must hold across all code
paths, service layer for cross-row decisions.** When adding a new constraint, place it
along the same axis — don't duplicate it in all three layers, and don't put a multi-row
check (existence, uniqueness against concurrent inserts) only in Pydantic.

Example: case-insensitive user-email uniqueness is a `UNIQUE INDEX (lower(email))` plus a
cheap pre-check in the auth service. `IntegrityError` from the index lands at the global
handler as a clean 409 — that's the safety net for the race the pre-check can't close.

**Authors deliberately have no name uniqueness** (migration `0004`): two real people can
share a name, and the system models that honestly rather than collapsing them into one
row. Bulk import therefore *always* creates new author rows; clients dedupe by `id`.

### Schema lives in `migrations/`, not `models.py`
`app/db/models.py` is the ORM mapping; the **migrations are the source of truth** for
schema (functional indexes, CHECKs, FK behavior, seed genres, `updated_at` triggers).
`tests/conftest.py` builds its schema from `Base.metadata` then **manually re-applies** the
functional indexes and seeds the genre table so tests match production behavior. If you add
a migration-only artifact (a CHECK, a trigger, a functional index), mirror it in
`conftest.py` or tests will pass while production breaks.

### Auth — refresh token rotation with reuse detection
`app/auth/service.py:refresh_tokens` is the load-bearing path. The contract:

- Access JWT (15 min) is stateless; refresh token (30 days, sha256-stored) rotates on every
  `/auth/refresh`, with `replaced_by_id` linking the chain.
- Presenting a token that has already been rotated → revoke **every** refresh token for
  that user. This is distinct from "revoked via logout" (`replaced_by_id IS NULL`), which
  is idempotent and never escalates.
- **The `session.commit()` before raising 401 in the reuse-detection path is load-bearing,
  not boilerplate.** Without it, the FastAPI session dependency rolls back the revocation
  and the attacker keeps access. Don't "clean it up."

Tests `test_refresh_reuse_revokes_all_sessions` and `test_logout_revokes_only_target`
pin both branches.

### Bulk import — per-row atomicity via SAVEPOINTs
`app/books/bulk.py:run_import` wraps each row in `session.begin_nested()` (SAVEPOINT).
One bad row fails alone; the rest of the batch commits. The handler creates the
`import_sessions` row **before** processing — so even a top-level parse failure (400)
leaves a queryable record and still counts toward the per-hour rate limit.

### Size limiting — middleware, not handler
`app/middleware.py:MaxBodySizeMiddleware` is pure ASGI: streams `receive()`, aborts with
413 the moment cumulative bytes exceed `settings.bulk_import_max_bytes` (2 MiB default).
Scoped to `/books/import` only. The handler does **not** re-check size — the middleware is
the authority. In production, nginx `client_max_body_size` is the primary gate; this
middleware is defense-in-depth.

### Observability — request ID is a ContextVar
`app/middleware.py:request_id_var` is set on entry, read by the JSON log formatter, and
included in **every error body** by the exception handlers in `app/exceptions.py`. Any
new exception handler must call the existing `_body()` helper (or equivalent) so the
request id is preserved — that's the property that lets ops correlate a 500 with one log
line.

### Route ordering in `app/books/routes.py`
`/export`, `/import` (POST + GET list), `/{book_id}/similar` are declared **before**
`/{book_id}` catch-alls. FastAPI matches in declaration order — reordering will silently
route `/books/export` to `get_book("export")` and return 404 or 422. When adding a new
non-`{book_id}` route under `/books`, declare it above the catch-all section.

## Keeping this file current

Update CLAUDE.md as part of the same change that invalidates it. Don't defer it — a stale
CLAUDE.md is worse than no CLAUDE.md, because future instances trust it.

**Update when your change**:

- Contradicts a claim here (e.g., the route-ordering rule no longer holds, the size cap moved
  out of middleware, refresh-token semantics changed).
- Introduces a new **architectural trap** of the same caliber as existing entries — a
  non-obvious invariant, a load-bearing line that looks like boilerplate, a place where the
  README is now wrong, a fixture/migration coupling that will silently break tests.
- Adds or removes a command someone needs to run the project (new lint step, test env var,
  migration workflow change).
- Resolves the "README divergence" section — either by fixing the README or by adding/
  removing items from the divergence list.

**Do NOT update for**:

- New endpoints, schemas, or service functions that follow existing patterns.
- Refactors that preserve the big picture.
- Bug fixes, dependency bumps, formatting, log-message tweaks.
- Anything you'd describe as "what changed" rather than "what someone needs to know to not
  break things." If it's already discoverable from the code in one read, it doesn't belong
  here.

The bar: would a future instance, starting cold, make the wrong call without this line?
If no, don't add it. When in doubt, leave it out — this file earns its keep by being short.

## Conventions worth knowing

- **Per-domain schemas.** Pydantic schemas live with the domain (`app/books/schemas.py`,
  `app/auth/schemas.py`). There is no central `app/schemas/` package.
- **No `_shared.py` / `_helpers.py`.** Inline single-caller utilities. Promote to a shared
  module only after a second caller exists.
- **No silent "future-proofing."** Fields that aren't used today don't get added today.
  Don't pad production code to satisfy an overspecified test — fix the test.
- **PATCH uses `extra="forbid"`** and distinguishes unset / null / unknown key (200 partial /
  200 cleared / 422). An empty `author_ids` on PATCH is 409 (books must have ≥1 author),
  not 422 — this is intentional asymmetry with POST.


## Anti-Patterns (avoid)

| Pattern | Use Instead |
|---------|-------------|
| `Optional[T]` | `T \| None` |
| `datetime.now()` | `datetime.now(timezone.utc)` |
| Class-based tests | Function-based pytest |
| Editing `app/db/models/__init__.py` | Models are auto-discovered |
| Top-level controller imports in `core.py` | Import inside `on_app_init` |
